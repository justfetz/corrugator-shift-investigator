### R1 — P1: every period PDF export fails

Location: `src/investigator/reports.py:47`.

The exporter calls `chart.get('title', f'Shift {chart["shift"]}: ...')`. Python evaluates the default expression before calling get, even when title exists. A calendar_heatmap has a title but no shift key. Week, month and accounting reports all raise `KeyError: 'shift'`. The browser's Download PDF action displays the bare message `'shift'`.

Reproduction: build any period report and click Download PDF, or run the supplied probe. Daily matrix PDF is covered by existing tests, but period export is not.

Proposed fix: select the title without eagerly evaluating a daily-only fallback, and use a chart-type-appropriate fallback. Add real Workbench/API export regression cases for week/month/accounting, partial windows and incomplete records. Parse/render representative PDFs and review page layout before claiming export readiness.

Acceptance: each supported report exports without exception, unauthorized/stale references still fail, and any truncated evidence is disclosed. Until then, Save text provides the narrative only.

### R2 — P2: comparison follow-up history is silently discarded

Locations: `src/investigator/agent.py:245`, `src/investigator/server.py:73`.

After Compare all shifts with the Shift control still set to 2, the agent changes context.shift to 3 (the last evidence shift). The next server request compares that focus with control shift 2 and replaces the context. The visible conversation still contains the comparison, but the agent sees only the new question.

Reproduction: same session, September 14, scope day, control shift 2; ask Compare all shifts, then Show speed. Probe output: first_focus=3; follow_history_length=1; follow_questions=[Show speed]. Existing direct-Agent follow-up tests bypass this server reset path.

Proposed fix: separate selected control state from conversational focus, or avoid changing selected context on completed comparisons. Add a server round-trip test proving retained history with unchanged controls and deliberate reset when controls actually change.

Acceptance: the second request receives the prior question under unchanged controls; changing day/shift/scope still clears incompatible context.

### R3 — P2: unavailable responses lose their explanation

Locations: `src/investigator/agent.py:207`, `src/investigator/openai_provider.py:153`.

The adapter substitutes a safe fixed message for cannot_answer, and the agent then discards even that message. A scripted unavailable response containing a useful next step produces only “Investigation stopped: unavailable. Any results below are partial.” The user gets no reason or recovery instruction.

Proposed fix: carry an application-owned, bounded explanation into sections. Prefer explicit unavailable categories and safe templates over blindly displaying unrestricted model prose. Test that unsupported questions show a useful next step and that no fake evidence is added.

Acceptance: unavailable capability is clearly identified and a supported next action appears in the UI and exports.

### R4 — P2: successful evidence is mistaken for fulfillment of the question

Locations: `src/investigator/agent.py:120`, `src/investigator/agent.py:210`.

Two deterministic probes demonstrate different sides of this gap:

- A scripted planner answers “Chart downtime by reason and explain how we can be better” with one KPI result and finish. The agent returns complete with zero charts.
- Offline “How can we improve profit on this shift?” triggers a production overview and complete status because the text contains shift. Profitability is not measured. The bare question “How can we be better?” is correctly rejected, so a small wording change changes the claimed success.

The code restricts tool permissions and prevents invented numerical summaries, but does not enforce requested deliverables or classify unsupported goals reliably. This is not evidence that a live model always fails; it is proof that the application permits these failures. No live model evaluation was run.

Proposed fix: define a bounded request/outcome contract that distinguishes completed evidence retrieval, requested chart fulfillment, unavailable objectives, and clarification required. Do not replace the small offline router with speculative general NLP or invent an overall improvement score. Evaluate broad requests using the rubric in TESTING.md.

Acceptance: unsupported profitability/savings requests explicitly disclose the limitation; a requested chart cannot silently count as fulfilled without a chart; legitimate exploratory questions can still retrieve relevant evidence with clear limits.

## Heatmap review

The direct `cell.style.backgroundColor = rgba(...)` fix is present and works in the browser with the restrictive CSP intact. Month cells display different shades and full detail. The UI positions the heatmap before KPI cards and tables. The backend and frontend use the same estimated-good output measure.

The accounting P2 test at September 29 displays September 29–October 26, two available days, missing-day hatching, partial status and zero ranking rows. Missing days do not enter the color scale. The selected missing cell says no complete synthetic record is available.

Remaining refinements, distinct from a data-transfer failure:

- The legend has no numeric endpoints and colors rescale per report. This is now documented; consider displaying the current minimum/maximum and scope directly.
- Darkest-cell day numbers have weak visual contrast; review the palette and text colors before accessibility sign-off.
- The old CSS custom-property background remains although available cells now use direct color. Remove or replace it during a focused cleanup, with browser validation.
- The renderer assumes a nonempty, internally valid row list. Its finite-value filter only controls the scale; it does not prevent tooltip formatting on malformed available rows. Current fixed fixtures satisfy the contract. Add explicit handling before supporting external input.
- Day clicks show details, not drill-down navigation. That behavior is now documented rather than implied as an investigation shortcut.
