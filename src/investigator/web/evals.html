How the investigator is checked

Back to the workbench

An agent's answer can read well and be wrong. These are the golden cases: fixed questions with fixed expected behaviour, run against the same synthetic records every visitor sees. Each case fails for one named reason. Press Run on any case to execute it on this server right now and see every check; press Run all for the score table. Offline cases cost nothing. Live cases replay a recorded model answer and never call a model from here.

Routing

Did the planner pick the right tool with the right arguments? Checkable because every tool call is a JSON object in the trace.

Faithfulness

Did every number in the answer come out of a tool row? Every numeric token in the prose must equal a tool-row value under one of the app's formats, a row count, or a stated rule constant.

Grounding

Does each finding cite evidence that exists? Citations are (result_id, row, field); each must resolve in the trace. A requested chart that could not be drawn must be disclosed.

Refusal

Does it say no when it should? Profit, yesterday, other dates, a shift outside the selected scope, email, SQL.
